SO-Arena · A benchmark for System One models

Benchmarking the capability spectrum and reliability of System One models

System One models decide in a single forward pass, without generating reasoning tokens. SO-Arena measures how well they decide across 11 domains and five capability families, and whether their decisions hold when the options change.

03 — Decision reliability

Does a decision hold when the options change?

Accuracy on one fixed option set overlooks whether a decision holds when the options change. SO-Arena changes them in two controlled ways and combines both tests into one reliability score.

S

Order stability

Each item is shown in its original order and in 12 reorderings. S is the share of reorderings in which the model keeps its answer, identified by content, rescaled so that random picks score 0 and full agreement scores 1.

N

Null discrimination

Each item is shown as it is and with its correct option removed. N = 2·AUC − 1 measures how well the model's probability that no option is correct separates the two copies: 0 is chance, 1 is perfect.

R

Reliability

The geometric mean R = √(S·N), positive only when both exceed chance, reported as a percentage next to the capability score.

05 — The benchmark

2,919 tasks in 11 domains

Tasks are built from established sources, checked by people, organized into domains and difficulty tiers, and posed through one decision interface: static questions and environment-based tasks in web and tool sandboxes.

How the leaderboard is scored

The original task is the unit of scoring, and domains are weighted equally so that larger domains do not dominate. Each domain contributes its hardest tier (Math: hard and very hard; untiered domains: all tasks), which makes the score more sensitive to differences on demanding tasks: 1,232 tasks in all.

06 — Evaluate

Evaluate your model

The evaluator reaches any model through an adapter, runs the static, tool and web tasks, and scores them with the leaderboard's rules. It needs Linux x86-64 and Python 3.12; the adapter protocol is documented in the repository.

Step 01 · Get the data 
./jev fetch-data --output /path/to/so-arena-data
export SO_ARENA_DATA=/path/to/so-arena-data
./jev verify
./jev setup

The release pins the dataset commit, the archive's SHA-256 and every data file; verify checks them.

Step 02 · Run your model 
export JEV_ENDPOINT=http://localhost:8000
./jev run --adapter adapters:http \
  --model your-model --out /path/to/new-run

Resume an interrupted run with the same arguments plus --resume; use --domain, --tier and --limit for a quick check.

Step 03 · Score 
./jev score --run /path/to/new-run \
  --output /path/to/report.json

The report gives the leaderboard score and its domain and tier components for the run.

Model inputs are public; answers, checker state and reference trajectories stay with the evaluator. Full instructions: the SO-Arena repository.
